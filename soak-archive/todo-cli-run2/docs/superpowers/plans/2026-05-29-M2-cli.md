# M2-cli: TDD Implementation Plan

Milestone: CLI layer for todo-cli (add + list commands)
Date: 2026-05-29
Scope: argparse CLI with `add` and `list` subcommands, output formatting, error handling, `python -m todo` support

## Overview

Build the CLI layer on top of the M1-storage foundation. M2 implements two of the
four spec commands (`add` and `list`), plus all shared CLI infrastructure: parser,
output formatter, `main()` entry point, `__main__.py`, and error handling.

Output follows the spec format: `<id> <status> <created> <text>`, one todo per line.
Exit codes: 0 = success, 1 = error (store failures), 2 = no command given.

Implementation lives in `todo/cli.py` (parser, formatter, main entry point) and
`todo/__main__.py` (enables `python -m todo`). Tests in `tests/test_cli.py`.

**Note:** `done` and `rm` commands are M3-done-rm scope. The parser in M2 only
registers `add` and `list` subcommands. List tests that need "done" items use
`TodoStore.done()` directly, not a CLI `done` command.

## Prerequisites

- M1-storage complete: `TodoStore` with `add()`, `done()`, `remove()`, `list_todos()`
- `tests/conftest.py` provides `store_path` and `store` fixtures

## Interface contract (from M1-storage)

```python
class TodoStore:
    def __init__(self, path: Path) -> None: ...
    def add(self, text: str) -> Todo: ...
    def done(self, todo_id: int) -> None: ...       # raises KeyError
    def remove(self, todo_id: int) -> None: ...     # raises KeyError
    def list_todos(self, include_done: bool = False) -> list[Todo]: ...

@dataclass
class Todo:
    id: int
    text: str
    status: str = "open"
    created_at: str = ...   # ISO-8601 UTC
```

## CLI command mapping (M2 scope)

| Spec command        | argparse subcommand | TodoStore method         | Exit code |
|---------------------|---------------------|--------------------------|-----------|
| `todo add "<text>"` | `add` (pos: text)   | `store.add(text)`        | 0         |
| `todo list [--all]` | `list` (flag: --all)| `store.list_todos(bool)` | 0         |
| *(no command)*      | —                   | —                        | 2         |

Commands deferred to M3-done-rm: `todo done <id>`, `todo rm <id>`.

## Design decisions

| Decision | Rationale |
|----------|-----------|
| Only `add` and `list` subcommands in M2 | `done` and `rm` are M3-done-rm per workflow.json |
| List tests use `TodoStore.done()` for setup | Done CLI command doesn't exist in M2; store API is tested in M1 |
| `main()` accepts `argv` parameter | Enables in-process testing without subprocess overhead |
| `--store` global option | Allows tests to use temp directories; default is `~/.todo/store.json` |
| Errors to stderr, data to stdout | Standard CLI convention; enables piping output |
| `_format_todo` is a module-level helper | Single responsibility; easy to test independently |
| `(OSError, ValueError)` catch around store ops | Covers corrupted JSON, permission errors, disk errors |
| No command → exit 2 | Distinguishes "user error" from "runtime error" (exit 1) |

## Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| `_format_todo` text with spaces breaks parsing | Text is last field — split with `maxsplit=3` when parsing |
| `args.id` type mismatch (str vs int) | argparse `type=int` enforces integer at parse time (M3) |
| Store init side effects in tests | `--store` flag + `store_path` fixture isolates to tmp dirs |
| `capsys` + `SystemExit` interaction | `main()` returns int, `__main__.py` does `raise SystemExit` — tests call `main()` directly |
| Corrupted store on any command | Outer try/except catches `(OSError, ValueError)` from any store op |
| Windows path in tests | Use `tmp_path` fixture, not hardcoded Unix paths |

## Scope boundaries

**In scope (M2-cli):**
- CLI scaffolding: cli.py, __main__.py, __init__.py
- `add` subcommand with formatted output
- `list` subcommand with `--all` flag
- `--store` global option
- Output format: `<id> <status> <created> <text>`, one per line
- Error handling: corrupted store, init failures
- `python -m todo` support

**Out of scope (M3-done-rm):**
- `done` subcommand and its error handling (exit 1 on unknown id)
- `rm` subcommand and its error handling (exit 1 on unknown id)

**Out of scope (general):**
- Interactive mode
- Tags, due dates, priorities
- Multi-user / network features
- Store migration or schema versioning
