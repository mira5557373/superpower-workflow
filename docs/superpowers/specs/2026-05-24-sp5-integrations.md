# SP5: Integrations -- Design Spec

**Date:** 2026-05-24
**Spec version:** 1.0
**Status:** Draft
**Roadmap:** SP5 of 7 -> v0.6.0
**Goal:** Connect superpower-workflow to external systems -- issue trackers, CI pipelines, chat, and PR tooling -- so `sw run` operates from ticket to merged PR without manual glue.

**Depends on:** SP2 (telemetry data feeds into notifications and PR summaries).

---

## 1. Overview

Five integration capabilities:

1. **GitHub Issue ingestion** -- `sw run --from-issue 42` reads an issue, converts it to a milestone, executes
2. **Linear/Jira tracker** -- read tickets via REST API, convert to milestones
3. **CI self-correction** -- when CI fails after push, pull logs, invoke claude -p to fix, re-push (84.6% success target)
4. **Slack notifications** -- real-time messages on milestone start/complete/fail
5. **PR auto-creation** -- after each milestone, create GitHub PR with summary, test results, cost

---

## 2. GitHub Issue Ingestion

### CLI

```
sw run --from-issue 42
sw run --from-issue owner/repo#42
```

### Flow

1. `gh issue view 42 --json title,body,labels,assignees` to fetch issue
2. Parse issue body into milestone spec (title = milestone name, body = spec text)
3. If issue has labels matching known categories (bug, feature, refactor), set milestone type
4. Create milestone in workflow-state.json, proceed to normal Phase A

### Config (workflow.json)

```json
{
  "integrations": {
    "github": {
      "default_repo": "owner/repo",
      "issue_label_map": {"bug": "fix", "feature": "feature", "refactor": "refactor"}
    }
  }
}
```

No token needed -- `gh` CLI uses ambient auth.

## 3. Linear/Jira Tracker Integration

### Config

```json
{
  "integrations": {
    "tracker": {
      "type": "linear",
      "api_url": "https://api.linear.app/graphql",
      "token_env": "LINEAR_API_TOKEN",
      "project_id": "abc-123"
    }
  }
}
```

### Flow

1. `sw run --from-ticket LIN-42` or `sw run --from-ticket PROJ-123`
2. Fetch ticket via REST/GraphQL (token from env var, never stored in config)
3. Map ticket fields to milestone: title, description, priority, assignee
4. On milestone complete, update ticket status to "Done" and post comment with PR link

### Supported trackers

- Linear: GraphQL API
- Jira: REST API v3 (`/rest/api/3/issue/{key}`)

Both use the same `tracker.py` interface with adapter pattern.

## 4. CI Self-Correction (Phase E)

### Trigger

After Phase D pushes and tags, if `gh run list --limit 1` shows a failing run:

### Flow (new Phase E)

```
Phase D: Push + Tag
  |
  v
Wait for CI (poll gh run list every 30s, max 10min)
  |
  v (if failed)
Phase E: CI Fix Loop (max 3 attempts)
  1. gh run view {run_id} --log-failed > ci_failure.log
  2. claude -p "CI failed. Logs:\n{last 200 lines}\nFix the issue. Commit."
  3. git push
  4. Wait for CI again
  5. If still failing, repeat (up to 3 attempts)
  |
  v (if all attempts fail)
  Mark milestone as ci_fix_failed, notify, stop
```

### State

New current_step values: `"ci_wait"`, `"ci_fix"`, `"ci_fix_failed"`

### Config

```json
{
  "integrations": {
    "ci": {
      "enabled": true,
      "max_fix_attempts": 3,
      "wait_timeout_seconds": 600,
      "poll_interval_seconds": 30
    }
  }
}
```

## 5. Slack Notifications

### Config

```json
{
  "integrations": {
    "slack": {
      "webhook_url_env": "SLACK_WEBHOOK_URL",
      "events": ["milestone_start", "milestone_complete", "milestone_failed", "ci_fix"]
    }
  }
}
```

### Implementation

Simple HTTP POST to incoming webhook URL. No SDK dependency.

```python
def notify(event: str, payload: dict) -> None:
    url = os.environ.get(config["webhook_url_env"])
    if not url:
        return
    text = _format_message(event, payload)
    httpx.post(url, json={"text": text}, timeout=10)
```

Events:
- `milestone_start`: "Starting milestone: {name}"
- `milestone_complete`: "Milestone {name} complete. Tests: {count}, Cost: ${cost}"
- `milestone_failed`: "Milestone {name} FAILED at {phase}. Error: {summary}"
- `ci_fix`: "CI fix attempt {n}/3 for {name}: {status}"

## 6. PR Auto-Creation

### Trigger

After Phase D (or Phase E if CI self-correction enabled), create PR.

### PR body template

```markdown
## {milestone_name}

{milestone_description}

### Changes
{git log --oneline plan_sha..HEAD}

### Test Results
- Tests added: {test_count_delta}
- Coverage: {coverage}%

### Cost
- Tokens: {total_tokens}
- Cost: ${total_cost}
- Duration: {duration}

Generated by superpower-workflow v{version}
```

### Implementation

```python
def create_pr(milestone, state, telemetry) -> str:
    body = _render_pr_body(milestone, state, telemetry)
    result = subprocess.run(
        ["gh", "pr", "create", "--title", milestone.name,
         "--body", body, "--head", branch, "--base", base],
        capture_output=True, text=True, timeout=30,
    )
    return result.stdout.strip()  # PR URL
```
